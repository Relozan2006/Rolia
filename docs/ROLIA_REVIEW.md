# Rolia — ревью ядра с фокусом на защиту сида

Дата: 2026-07-09. База: `main @9b10cdb` (build 16), MC 26.1.2, Canvas/Folia, Java 25.

> **ОБНОВЛЕНО 2026-07-09 — дыра №1 ИСПРАВЛЕНА в коде.** Мешивание сида в размещении починено
> безусловно (сервер новый — миграция не нужна) и проверено на автономном харнессе: размещение
> теперь зависит и от сида, и от соли, детерминировано; заодно исправлен `getBits(64)`/`nextLong()`.
> CI усилён: двойной запуск сервера + проверка сида и ошибок старта; релиз только при зелёном тесте.

## TL;DR

Главная цель проекта — «сид нельзя вычислить». Сейчас она выполнена **наполовину**:

- **Форма рельефа защищена.** Базовый террейн, биомы, аквифер, шум руды, климат идут через
  `Hashing.expandLevelSeedTo1024Bits(...)`, где сид солится секретной солью. Это проверено —
  результат зависит и от сида, и от соли.
- **Размещение НЕ защищено.** Структуры, декорации/фичи, slime-чанки, End-шпили, жеоды идут через
  `WorldgenCryptoRandom`, и его поток случайных чисел **не зависит ни от сида, ни от соли** (проверено
  экспериментально, см. ниже). То есть координаты структур и декораций одинаковы на любом сервере Rolia
  вне зависимости от сида — взламывать нечего, всё публично.

Это дыра №1 и она бьёт ровно в цель проекта. Ниже — доказательство, точечный фикс и почему его нельзя
просто «выкатить» (ломает генерацию существующих карт).

## 1. КРИТИЧНО — RNG размещения игнорирует сид и соль

### Где
`WorldgenCryptoRandom.moreRandomBits()`:

```java
private void moreRandomBits() {
    message[3] = counter++;
    System.arraycopy(getHashedWorldSeed(), 0, randomBits, 0, 8); // кладём хэш мира в randomBits...
    Hashing.hash(message, randomBits, cachedInternalState, 64, true); // ...и тут же затираем!
}
```

А `Hashing.hash(...)` хеширует **только** `message` и игнорирует переданный `output`/`state`:

```java
public static void hash(long[] message, long[] output, long[] state, int outputBytes, boolean finalBlock) {
    long[] result = hashWorldSeedInternal(message);          // хэш только message
    System.arraycopy(result, 0, output, 0, Math.min(result.length, output.length));
}
```

`message` = {упакованные X/Z, dimension+salt, typeSalt.ordinal, counter, 0, 0, 0, 0}. Ни `worldSeed`,
ни соль сюда не входят. Значение `getHashedWorldSeed()` (единственное место, где сид/соль могли бы войти
в этот путь) вычисляется и выбрасывается.

### Доказательство (автономный тест на настоящем `Hashing.java`)

Три потока `nextInt(1_000_000)` для одних и тех же координат/домена, меняем только сид и соль:

```
worldSeed=1111 salt=ALPHA: [68675, 739489, 162951, 415769, 103661, 363174, 40471, 643146]
worldSeed=9999 salt=ALPHA: [68675, 739489, 162951, 415769, 103661, 363174, 40471, 643146]
worldSeed=1111 salt=BRAVO: [68675, 739489, 162951, 415769, 103661, 363174, 40471, 643146]

A==B (другой СИД проигнорирован?) : True
A==C (другая СОЛЬ проигнорирована?): True

[контроль] base-terrain expand(): чувствителен к соли: True, чувствителен к сиду: True
```

Вывод: путь `WorldgenCryptoRandom` — публичная функция координат. Путь `expand()` (рельеф) — корректен.

### Что затронуто размещение-путём
Структуры (`RandomSpreadStructurePlacement`, `StructurePlacement`, `Structure`, `JigsawPlacement`),
декорации/фичи (`setFeatureSeed`/`setDecorationSeed` → `Salt.DECORATION`/`POPULATION`), slime-чанки,
`EndSpikeFeature`, `GeodeFeature`.

### Фикс (точечный, одна функция)
Нужно, чтобы `randomBits`, предзаполненный `getHashedWorldSeed()` (= хэш от worldSeed+соль), реально
входил в хэш — как ключ/начальное состояние, а не затирался. Варианты:

- в `Hashing.hash(...)` использовать `output` (и/или `state`) как начальное состояние вместо чистого IV;
- либо в `moreRandomBits()` подмешать `getHashedWorldSeed()` в `message` перед хешированием
  (напр. XOR в `message[4..7]`/`message[0..3]`).

### Почему нельзя просто выкатить
Это меняет **весь** поток размещения → у существующих карт поедут границы чанков (швы). Пути миграции:

1. **Новый мажор / версия формата мира** — чистый вариант, включить для всех новых миров.
2. **Конфиг-флаг** `secure-seed.mix-world-seed`: по умолчанию текущее поведение (старые карты не трогаем),
   включать осознанно для новых миров.
3. Привязать поведение к version мира при создании.

Рекомендация: сделать фикс за флагом (вариант 2) и включать по умолчанию только для свежесозданных миров.

## 2. Вторичные баги в том же (замороженном) пути

- **`getBits(64)` возвращает 0.** В Java `1L << 64 == 1L` (сдвиг берётся по модулю 64), поэтому
  `(1L << 64) - 1 == 0`. В `getBits` при `count==64` (это `nextLong()` под secure seed) маска обнуляется →
  `nextLong()` вырождается. `nextInt(bound)` с обычными границами не затронут (там count < 64).
- Обе правки — только вместе с разморозкой (новый мажор), т.к. тоже меняют генерацию.

## 3. HIGH — защита секрета (соли)

- **Соль на диске — СДЕЛАНО (эта сессия).** `rolia-seed.properties` теперь ставится в права
  «только владелец» (POSIX 0600, на Windows — best-effort). Раньше файл создавался с umask по умолчанию и
  на шаред-хосте мог читаться другими пользователями, а соль — это мастер-ключ всей защиты.
- **`/seed` всё ещё печатает сырой levelSeed.** Патч `SeedCommand` не тронул строку
  `commands.seed.success`, а лишь добавил feature seed. Некритично (секрет — соль, а не levelSeed: даже
  зная сырой сид, без соли генерацию не воспроизвести), но для defense-in-depth стоит скрыть/загейтить
  сырой сид и оставлять только feature seed. Мелочь: ключ `"Feature seed: %s"` идёт через `translatable`
  без реального перевода — косметика.
- **Псевдо-BLAKE3 — не аудированная крипта.** Константы `BLAKE3_IV` — это перемешанные половинки IV
  SHA-512, а не настоящий BLAKE3; 5 раундов упрощённого ARX. Для целей «сид не вычислить» это,
  вероятно, достаточно на практике, но формально это самодельный хеш без анализа стойкости. Настоящий
  BLAKE3/SHA-256 был бы надёжнее — но это снова worldgen-ломающее изменение (только новый мажор). Как
  осознанный выбор ради совместимости с Foldenor — ок; предлагаю зафиксировать это в доке как
  «непроверенная криптопримитивная функция, не полагаться как на криптостойкую вне игрового контекста».

## 4. MED — качество и эксплуатация

- **Канал сборки `Running unknown build channel` — СДЕЛАНО (эта сессия).** Причина: рантайм тянул
  `buildStatus` сетевым запросом к API CanvasMC (`Util.CANVAS_CLIENT.getBuild`), которого форк не знает →
  падало в `UNKNOWN`. Теперь для форка выставляется локальный `STABLE` (совпадает с `channel = STABLE` в
  `gradle.properties`), без похода в сеть. Заодно убирает нежелательный phone-home на инфраструктуру Canvas.
- **SIMD + флаги запуска — СДЕЛАНО (эта сессия).** `start.sh`/`start.bat`/`LAUNCH.md` с
  `--add-modules=jdk.incubator.vector` (Canvas просил это в логе) и тюненным G1. Чистый рантайм, worldgen
  не трогает.
- **Апдейт 26.1.2 → 26.2.** Вышел стабильный MC 26.2 («Chaos Cubed»), Rolia на один game-drop позади.
  Отдельный трудоёмкий трек: переналожить seed-патчи на ветку Canvas под 26.2, риск конфликтов и сдвига
  worldgen при смене mappings. Делать отдельно от текущих правок.
- **Мелочи:** соль короче 64 символов молча регенерируется (стоит логировать явнее, что кастомная соль
  отклонена); можно добавить `/canvas`-подобную команду показа статуса secure-seed (вкл/выкл) без утечки
  соли.
